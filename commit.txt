Fix USGS M2M authentication docs and add missing access-request step

The core pygeofetch/providers/usgs.py implementation was already
correct (M2M Application Token, not password) but the surrounding
documentation had drifted into showing the wrong auth method in four
separate live code examples, and was missing a genuinely necessary
prerequisite step entirely.

Verified directly against USGS's own official M2M Application Token
documentation, plus cross-confirmation from independent real projects
(landsatxplore, rslearn) that broke on the same real deprecation date:
the Application Token authenticates "instead of your ERS password" --
it replaces password auth, it is not used alongside it. USGS
deprecated the password-based /login endpoint on 2025-02-26.

Found and fixed a real, previously undocumented gap: M2M API access
must be explicitly requested and approved on a USGS account before a
generated token will actually work. This is a separate, one-time step
from generating the token itself, and skipping it produces a token
that silently doesn't work. Added the real, confirmed URL:
https://ers.cr.usgs.gov/profile/access (select "MACHINE" access type;
real accounts report approval taking a couple of days).

pygeofetch/providers/usgs.py:
- authenticate()'s docstring and AuthenticationError message now
  describe both real steps in order (request access, then generate
  token), with both real URLs, and state explicitly that the token
  replaces rather than supplements the password
- No behavioral change; verified against existing usgs and
  earth_explorer_additional test suites (32 tests, both still pass
  unchanged)

Documentation (core-features/providers.md, core-features/
authentication.md, reference/python-api.md):
- Fixed four separate live code examples in authentication.md that
  showed `--password`/`password=` for USGS specifically (CLI add,
  environment-variable loading example, provider auth-type table, and
  the final Python snippet), each replaced with the real
  --api-key/api_key= M2M token pattern
- Fixed one more matching occurrence in python-api.md found during a
  full-tree sweep
- providers.md: corrected the USGS status-table label from "Username/
  password (M2M)" to "Username + M2M Application Token", and expanded
  the entry with the real two-step process and both URLs
- Incidentally caught and confirmed as already-correct: two remaining
  "terrabotics" mentions in providers.md and roadmap.md are legitimate
  historical references explaining that provider's earlier removal,
  not stale live references -- left unchanged after verification
